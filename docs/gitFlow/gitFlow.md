## Программа управления проектами:

📌 Получите лично

## Работа над таской начинается:

📌 С назначения ответственного за неё и перемещение в зону In progress

## Список веток:

📌 master, develop, ${feature}

## Правила именования веток:

📌 по названию фичи, например main-form-component

## Правила именования коммитов в feature-ветках:

📌 `${feature part} ${action}`

## Правила ревью:

📌 При намерении влить feature ветку в develop открывается pull request, второй разработчик из вашей команды должен заревьюить его и одобрить. При merge-конфликтах ответственен инициатор мержа и должен его исправить

При намерении влить в master ветку открывается pull request и ваш куратор проекта должен сделать код-ревью. Этапы, на которых будет такой мердж обсуждаются индивидуально на митингах

📌 При открытии PR задача перемещается в графу In review. Куратор проекта тегается в чате при работе с master веткой
